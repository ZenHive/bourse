## Findings

1. **Rerouted WebSocket connection ownership was incomplete (fixed).** A USD-M
   `watch_*` call that switched from `/public/ws` to `/market/ws` opened a new
   `ZenWebsocket.Client`, but a failed subscription left it running and
   `unsubscribe/1` only sent an unsubscribe frame. The watch handle now records
   whether it owns a routed connection. Failed subscriptions close it before
   returning or reraising, and unsubscribe closes it after the unsubscribe
   attempt while preserving the caller's original shared socket. Public docs
   and `[Unreleased]` now state this lifecycle.

2. **Task 618's BUGS status was stale (fixed).** The fixed block named orphaned
   pre-rebase commit `8dc570a`, said the already-landed workaround could be
   retired “after this lands,” and left a second `Status` header claiming the
   bug was still triaged. It now names landed commit `f5ad332`, uses present
   tense, and labels the retained evidence as the original triage.

3. **`Bourse.WS.Handle` was below the standard coverage tier (fixed before
   mutation).** Baseline coverage was 66.67% because the default constructor
   arity was not exercised. The constructor and ownership default are now
   asserted; final coverage is 100% for `Bourse.WS.Handle` and 81.03% for
   `Bourse.WS`.
